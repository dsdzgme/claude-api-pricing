同价位段里，Sonnet 5.5 是 Anthropic 目前推荐大多数应用起步的型号，能力和成本的平衡点就在这：编码助手、面向客户的聊天、内部工具，用它当默认一般不会错。Haiku 4.5 负责量大、对延迟敏感的活——给工单打标签、审核评论、从短文档里抽字段，$1/$5 的价格足以跑遍整个数据集的每一行。Opus 5.5 留给多步 agent 规划、法律和金融文档分析这类硬任务，它的价格是 Sonnet 5.5 的两倍，只有当额外那点推理质量真的会改变结果时才值得。

生产系统里常见的做法是加一个路由：先用 Haiku 给请求分诊，标记为复杂的转给 Opus，中间地带交给 Sonnet。这一招省下的钱，比调任何参数都直接。

## 计费方式：钱是怎么扣的

Claude API 没有订阅的概念。你预先充值或绑定信用卡，每个请求按 token 从余额里扣，大多数组织用的就是预付费模式。注意它和 Claude.ai 网页版的 Pro/Max 订阅完全是两套账——Pro 订阅不包含任何 API 额度，反过来也一样。

一个 token 大约相当于 4 个英文字符，或 0.75 个英文单词，具体数量因语言而异。你发送的内容（系统提示词、对话历史、文档）和模型生成的内容，分别按各自的费率折算。

两个直接影响账单的细节：

- `max_tokens` 是每次调用的必填参数，限制的是本次回复的最大长度，只封顶生成量，不等于预留、也不等于按这个数计费。
- 响应里的 `usage` 字段会记录本次调用的输入、输出和缓存 token 数。要对账，以它为准，别自己估。

### 算两笔真实的账

例一：用 Claude Opus 5 做一次普通问答，发送 1,000 个输入 token，收到 300 个输出 token。

- 输入：1,000 × $5 ÷ 1,000,000 = $0.005
- 输出：300 × $25 ÷ 1,000,000 = $0.0075
- 合计约 $0.0125。

例二：用 Haiku 4.5 给 1,000 封邮件分类，每封读入约 2,000 token、写出 300 token。

- 输入合计 200 万 token = $2
- 输出合计 30 万 token = $1.50
- 总计 $3.50，走 Batch 模式再减一半。

同一个分类任务换成 Opus 5.5，光输入单价就是四倍。量大的时候，选型是最大的杠杆。

## 把账单降下来的三种办法

### Prompt Caching：重复上下文一折计费

如果每次请求的开头都是同一段长内容——很长的系统提示词、风格指南、产品目录、法律模板——这部分可以缓存。缓存读取只按基础输入价的 **10%** 计费，写缓存多花的钱，复用一次就回本。

写入端不是免费的：5 分钟时效的缓存写入收输入价的 1.25 倍，1 小时时效收 2 倍。Opus 5.5 和 Fable 5.1 的缓存读取还更便宜，分别为 $0.20 和 $0.25 每百万 token。

| 型号 | 缓存读取（每百万 token） | Batch 输入 / 输出（每百万 token） |
| --- | --- | --- |
| Claude Fable 5.1 | $0.25 | $5 / $25 |
| Claude Opus 5.5 | $0.20 | $2 / $10 |
| Claude Sonnet 5 | $0.20 | $1 / $5 |
| Claude Haiku 4.5 | $0.10 | $0.50 / $2.50 |

*费率以官方 2026 年 9 月底公布的价格为准。*

缓存是按前缀匹配的，请求开头一有改动，后面的缓存全部失效。所以稳定的内容放前面，用户每次变化的输入放最后。也别把缓存当成提示词臃肿的借口——塞一堆模型用不上的文档再靠缓存兜底，方向就反了。

### Batch API：不赶时间的任务五折

不需要立即拿到结果的活——隔夜跑评测、批量抽取、整批文档摘要——可以走 Batch API，输入输出都按半价计，结果在 24 小时内返回。Batch 模式下 Opus 5 降到 $2.50/$12.50。实时聊天、自动补全这类用户等着秒回的场景，老实用标准接口。

### 模型路由：简单任务别用 Opus

前面说的路由模式再强调一次：Haiku 跑量，Sonnet 当默认，Opus 和 Fable 只在难题出现时上场。一个设计合理的路由系统，能让大多数请求根本碰不到贵模型。

这三种办法还能叠加：能批处理的进 Batch，稳定前缀上缓存，路由负责分流。

## Claude API 和 Claude Pro 订阅，选哪个？

两者解决的是不同问题。Pro 订阅是固定月费，给人在网页和应用里聊天用；API 是让程序调用模型，按量计费。你只是自己写作、查资料，订阅就够了；要给产品接能力、跑自动化、批量处理数据，才需要 API。不少团队是两边都开着：个人订阅日常用，生产环境走 API。

## 官方 Claude API 开通流程，五步走通

官方渠道的入口叫 Anthropic Console（开发者平台，直接搜索这个名字就能找到），流程五步：

1. 注册账号并创建组织，这是所有用量的计费单位。公司项目建议单独建 workspace，把不同环境的账单和限额分开。
2. 在账单页添加支付方式，支持信用卡或预付充值。新账号默认是限额很紧的免费档，很多人第一次请求就报 429 限流错误，原因往往就是跳过了这一步。
3. 在设置的 API Keys 页面生成密钥。密钥只显示一次，当场复制保存。
4. 把密钥存成环境变量（如 `ANTHROPIC_API_KEY`），或放进 `.env` 文件并立刻加入 `.gitignore`。泄露到公开仓库的密钥通常几小时内就会被扫描程序盯上，账单算你的。
5. 装官方 SDK（Python：`pip install anthropic`；Node.js：`npm install @anthropic-ai/sdk`），跑通最小调用后再扩展系统提示词、工具调用和流式输出。

python
import anthropic

client = anthropic.Anthropic()  # 自动读取 ANTHROPIC_API_KEY 环境变量

response = client.messages.create(
    model="claude-sonnet-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "用两句话解释什么是 API 速率限制。"}]
)

print(response.content[0].text)
